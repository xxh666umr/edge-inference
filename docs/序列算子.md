# 扩展算子：GRU / LayerNorm / Attention / softmax

本仓库的推理库原本只覆盖 CNN 分类链路（conv / pool / fc / softmax）。
为了对齐“通用边缘推理框架”的范围（导师资料中前人工作还包含 RNN / attention / LayerNorm），
本阶段在 `csrc/nn.c` 中新增了下列算子，并用 numpy 做了逐元素对齐测试。

## 算子清单

| 算子 | 接口 | 语义（与 PyTorch 对齐） |
|---|---|---|
| 向量 softmax | `softmax_probs(logits, n, scale, probs)` | `probs = softmax(logits*scale)`，int32 logits + float scale |
| 单步 GRU | `gru_cell_f32(w_ih, w_hh, b_ih, b_hh, x, h, h_new, in_dim, hidden)` | `r=σ(W_ir x+b_ir+W_hr h+b_hr)`，`z=σ(...)`，`n=tanh(W_in x+b_in + r*(W_hn h+b_hn))`，`h'=(1-z)n+zh` |
| LayerNorm | `layernorm_f32(x, gamma, beta, y, n, eps)` | `y=(x-mean)/sqrt(var+eps)*gamma+beta`（有偏方差） |
| 单头 attention | `attention_f32(q, k, v, out, seq, d, scores)` | `scores=QKᵀ/√d`，行 softmax，`out=softmax·V` |

布局约定：
- GRU：`w_ih [3H][input_dim]`、`w_hh [3H][hidden]`、`b_* [3H]`，gate 顺序 **r, z, n**（与 `nn.GRUCell` 一致）；
- LayerNorm：逐元素 gamma/beta，长度 = 特征维；
- attention：`q/k/v` 均为 `[seq_len][d_model]`，`scores` 由调用者提供 `[seq][seq]` 缓冲。

## 精度

`tests/test_seq_ops_parity.py`：随机 14 组用例（softmax×4、GRU×4、LayerNorm×3、attention×3），
共比对 102 个元素，**与 numpy float64 最大误差 ≈ 2e-7，全部 PASS**（容差 1e-5）。


## 性能与限制（重要）

- 目前这 4 个算子是 **float32 参考实现**：F103 没有 FPU，全部走软浮点，速度较慢；
  以 16 维 hidden、8 步序列的 GRU 估算，单步约 4~8 ms、8 步约 30~60 ms。
- 适合 M4F / H743 等带 FPU 的 MCU，或作为 PC 端参考/验证实现。
- **int8 定点化**（sigmoid/tanh LUT、定点 LayerNorm、int8 attention）是后续工作；
  接口可保持不变，内部换成定点即可。
- GRU 的 hidden 上限当前为 64（`GRU_MAX_H`，避免动态内存）；更大模型需调整该常量。

## 为什么现在加这些

1. 导师资料里的“通用边缘推理”包含 RNN/Transformer 组件，补齐后框架覆盖范围一致；
2. 这些算子与量化导出脚本解耦，后续训练出 RNN/attention 小模型时可直接复用；
3. 与 CNN 算子共用同一套对齐测试方法（C 探针 + MSVC 编译 + numpy 参考），
   保证“写进库里的算子都是被验证过的”。
